# mockit 分发与接入 规格

来源:夜链 20261009-114053(评审收敛 1 轮修订;object = .xcheck/20261009-114053/proposal.md,决策 D1~D15、问题记录 F1~F7 同环)。
术语遵守仓根 CONTEXT.md 词汇表(接入方/用户/提交/候选/审核/裁决/批注/待审已审/钉住/清理)。

## Problem Statement

mockit 目前只在开发机手工构建使用。其他机器上的 AI agent(接入方)无法安装:二进制没有分发渠道,配置要逐机手工改绝对路径,接入方也不知道何时、如何使用三工具。需要一个"零手工配置"的分发与接入机制,使任何一台自家机器上,用户一句话就能让本机 agent 完成安装并正确用上 mock 审核闭环。

## Solution(用户视角)

用户在 GitHub release 页获得四件套(四平台二进制、安装引导、agent 使用指南、技能文件)。在新机器上,用户对自己的 agent 说"按 mockit 最新 release 的 INSTALL.md 装",agent 照引导完成:判平台下载二进制 → 重命名为统一命令名 → 放入 PATH → 按合并纪律把 mockit 写入用户级 MCP 配置 → 安装全局技能 → 两级验收。装完后该机所有项目零逐项目配置;agent 在用户需要 mock 页面拍板时自动按技能工作流提交、贴 URL、取回裁决。

## User Stories

1. 作为用户,我想在新机器上对 agent 说一句"按 mockit 最新 release 的 INSTALL.md 装"就完成安装,以便零手工配置接入。(D10)
2. 作为接入方,我想要一份自包含的安装步骤书(INSTALL)与触发式技能(SKILL),以便正确执行安装、并在用户需要页面拍板时按工作流提交/贴 URL/取裁决。(D10/D5/D7 自包含)
3. 作为用户,我想每台机器只装一次(用户级 MCP 配置 + 全局技能),以便所有项目零逐项目配置。(D11/D5/D9)
4. 作为用户,我想让 release 四件套同 tag 版本对齐(内嵌版本 = tag = 资产),以便任意平台同一入口安装、版本可核对、排障可凭版本区分。(D12/D15)
5. 作为用户,我想让安装引导强制"备份 → 读 → 只合并 mcpServers 下的 mockit 键 → 校验 → 写回"写 ~/.claude.json,以便目标机既有配置不被破坏。(D11)
6. 作为用户,我想要两级安装验收(绝对路径立验版本输出;重启 Claude Code 进程后终验三工具可见),以便安装成败当场可判、不被 PATH 未刷新误导。(rev1 决策 11)
7. 作为发布者,我想要一条命令组装四件套并打印发版命令(含出厂检查:内嵌版本输出 = tag),以便晨间一键发版且版本一致性有兜底。(D12/D15)

## Implementation Decisions

- **零业务代码**:除版本常量 bump(0.1.0→0.1.1,发布元数据,D15 澄清)外不改任何业务代码;不写安装器子命令。
- **四件套资产契约**:release 资产 = windows-amd64(.exe) / darwin-amd64 / darwin-arm64 / linux-amd64 四平台二进制 + INSTALL(安装引导) + AGENT-GUIDE(agent 使用指南,已存在,随包附带) + 技能文件(skills/mockit/SKILL.md);仓内文件为正本,发版打包,同 tag 对齐;tag 从 v0.1.1 起。
- **二进制规范化(强制)**:资产名带平台后缀;安装时 Windows 重命名 `mockit.exe`、macOS/Linux 重命名 `mockit`,Unix 补可执行位;此后 MCP 配置行四平台统一 `{"command":"mockit","args":["mcp"]}`。
- **PATH 落位**:二进制进 PATH;Windows 安全写法 = PowerShell 用户级 Path 读-改-写(避开 setx 1024 截断,保留既有条目);macOS/Linux 放常规 bin 目录。
- **用户级 MCP 配置(强制合并纪律)**:`~/.claude.json` 为目标机存量文件,禁止整文件替换;必须"写前备份 → 结构化读取 → 仅在 mcpServers 下合并/更新 mockit 一个键 → JSON 校验 → 写回"。
- **技能落位与内容**:全局 `~/.claude/skills/mockit/`;自包含一页纸 = 触发时机(要做 mock 页面/多方案对比) + 压缩工作流(submit → 贴 URL 提醒用户手机拍板 → get_review 取裁决) + 常见错误应对(external_url 配置/serve 卡死/启动失败/超时);不引用仓内路径。
- **INSTALL 内容契约**:判平台下载 → 重命名 → PATH(Windows 用户级安全写法) → 合并纪律写配置 → 装 skill → 两级验收 → 安全事实句("默认监听 0.0.0.0、无鉴权,只在受信网络运行,勿暴露公网") → NetBird 前提与 external_url 排障指引;可被 agent 直接照做,亦可供人肉安装。
- **README 接入节**:新增"分发到其他机器"节(入口话术 = 让目标机器 agent 按 INSTALL 装);"CC Switch 模板警告"节改措辞为用户级为主、项目级 .mcp.json 为例外手段。
- **发版流程**:发布脚本组装四件套(构建四平台产物 + 收集三文档)并打印发版命令;出厂检查 = 本地运行 mockit version,输出必须等于 tag 版本;实际创建 release 为人工动作(晨间)。
- **发布纪律(过程)**:夜链分支实现全部文件与脚本;不自动创建 release、不自动开 PR;跨机真装验证为人工动作。
- **账本不入库**:.xcheck/ 加入 .gitignore(夜链账本目录)。

## Testing Decisions

- 只测外部行为,不测实现细节;沿用仓内 internal/*_test.go 先例;纯文档交付物无单元测试,以票级评审逐条对照验收标准为验收。
- 版本 bump:本地构建后运行 `mockit version`,断言输出 0.1.1(= 未来 tag)。
- 发布脚本:干跑断言组装产物齐(四平台文件名 + 三文档)且出厂检查逻辑拒绝版本不一致;`go build`/`go vet` 通过。
- 文档票:票级评审对照内容契约逐项核对(存在性 + 关键节覆盖 + 三份文档说法一致,含配置行/重命名/验收口径)。

## Out of Scope

- 跨机汇总、页面内容取回工具、鉴权、推送、集中部署、用户体系(维持 MVP 共识)。
- dsh 侧(NUC10)配置——等其 MCP 支持定案。
- 默认监听地址收紧(bind 属产品决策,留用户另议;本规格只把安全表述事实化)。
- 自动创建 GitHub release / 自动开 PR(发布动作只能人做)。
- F6(Windows PATH 读用户级持久值的措辞细化)、F7(macOS 浏览器下载 xattr 说明):评审非阻断建议,未获用户采纳,不进本规格;留晨报供用户决定。
- MCP 工具面、URL 基址、锁协议、清理节律等既有行为零改动。
