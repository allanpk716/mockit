# mockit · 页面候选审核闭环

mockit 是跑在**你所在机器**上的审核服务:你提交 1~6 个完整可看的 mock 页面候选,拿到手机可直接打开的审核链接;用户在手机上全屏对比、投票或打回;你取回裁决继续干活。**提醒用户去看,是你的职责——服务器零推送。**

接入前提:mockit 三个 MCP 工具已在本机配好(安装与 MCP 配置方法见 mockit release 附带的 INSTALL.md);不需要预先启动服务,第一次调用任何工具时自动拉起本机服务,首次调用可能多花几秒。

## 触发时机

用户提出以下任一需求时使用本技能:

- 要做 mock 页面 / 原型页面 / 演示页面;
- 要在多个设计方案之间对比、拍板;
- 想在手机上真实看页面效果;
- 对已有方案提了修改意见,需要重新出候选确认。

产出物永远是 1~6 个**完整可看的页面候选**(HTML,能直接打开交互),不是截图、线框图或文字描述。用户需要"亲眼看、做选择"时才走 mockit;纯代码问题直接写代码。

## 工作流

1. **做出候选**:1~6 个,每个是完整可看的独立页面。提交时每个候选二选一给内容:`html`(内联全文)或 `path`(本地 .html/.htm/.zip 文件),并带必填 `label`;`title` 必填,`note` 可选(给用户看的背景说明)。
2. **`mockit_submit` 提交**:返回 id、审核页 URL、各候选 URL。**拿到 URL 立刻原样贴给用户**,并提醒在手机上打开、用页面底部按钮拍板(手机需与这台机器在同一 NetBird 网络)。
3. **等用户回话**(说"审完了/选好了")后调 **`mockit_get_review`**(参数 id)取裁决,不要高频轮询:
   - `approve` / `choose`(含选中候选)→ 按选中候选继续实现;
   - `reject` + 批注 → 按批注修改后**重新 submit**(不支持覆盖更新,历史留痕是特性)。
4. **`mockit_list`**(status / limit 可选):需要翻旧账时用,查看历史提交简列与当时选了哪版。

## 错误应对

- 报"无法确定手机可达地址" → 请用户在 `~/.mockit/config.json` 配 `"external_url": "域名或IP"`(只填主机名,不带端口),然后重试;
- 报"疑似卡死,请人工处置" → 请用户手工结束进程;下次调用工具时服务自动复活;
- 报"启动中退出,可手工运行 mockit serve 查看报错" → 请用户手工跑一次 `mockit serve`;
- 调用超时 → 稍等重试一次。

## 约束

- 候选 1~6 个;单文件 ≤20MB;zip 必须在根目录含 index.html;
- 服务器不做构建、不做鉴权(只在受信网络可达)——要构建的产物你自己构建完再交;
- 已审(reviewed)是终态不可改;要改就重新提交;
- 页面文件 14 天自动清理(已审记录留 90 天)——**别向用户承诺"链接永久有效"**;服务重启若端口漂移,旧链接失效,重新提交拿新链接;
- 重要裁决结论自己存档到对话或笔记里;
- 用户不主动看就没人审——**提醒用户去手机上拍板,是你工作流的必做一步**。
