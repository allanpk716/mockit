# mockit · 页面候选审核闭环

mockit 是跑在**你所在机器**上的审核服务:你提交完整可看的 mock 页面候选(推荐 3~5 个,上限 1~6),拿到可直接打开的审核链接;用户在手机或电脑上全屏对比候选、在批注面板里裁决(选它/通过/打回,打回必写批注);你贴完链接立刻挂起等待,裁决一落就取回继续干活。**提醒用户去看,是你的职责——服务器零推送。**

## 铁律:请用户审核,必附审核链接

只要你在消息里请用户去审核、或提醒用户去看,**同一条消息里必须给出审核链接**——没有例外:刚提交后、等待超时提醒时、打回重交后、用户问"在哪看"时,都一样。

- 审核链接单独占一行,写完整地址(形如 `http://主机:端口/s/<id>`),原样照抄工具结果;不要藏进 markdown 链接文字,不要只报 id。
- 候选链接可选,列在审核链接下方。
- 手里没有审核链接了(如上下文已压缩)→ 用提交 id 调一次 `mockit_get_review`,待审结果里附有审核链接。

接入前提:mockit 的 MCP 工具已在本机配好(安装与 MCP 配置方法见 mockit release 附带的 INSTALL.md);不需要预先启动服务,第一次调用任何工具时自动拉起本机服务,首次调用可能多花几秒。

## 触发时机

用户提出以下任一需求时使用本技能:

- 要做 mock 页面 / 原型页面 / 演示页面;
- 要在多个设计方案之间对比、拍板;
- 想在手机或电脑上真实看页面效果;
- 对已有方案提了修改意见,需要重新出候选确认。

产出物永远是 1~6 个**完整可看的页面候选**(HTML,能直接打开交互),不是截图、线框图或文字描述。用户需要"亲眼看、做选择"时才走 mockit;纯代码问题直接写代码。

## 工作流

1. **做出候选**:推荐 3~5 个(上限 1~6),每个是完整可看的独立页面。候选在手机、电脑上各显示成什么样,完全由页面自身决定(mockit 原样铺满屏幕加载,不模拟机型)——按产品的目标设备做;目标设备不明或两端都要看,就做成响应式。提交时每个候选二选一给内容:`html`(内联全文)或 `path`(本地 .html/.htm/.zip 文件),并带必填 `label`;`title` 必填,`note` 可选(给用户看的背景说明)。
2. **`mockit_submit` 提交**:返回 id、审核链接、各候选链接。**立刻按铁律把审核链接贴给用户**,并提醒在手机或电脑上打开、用页面底部按钮拍板(设备需与这台机器在同一 NetBird 网络)。
3. **贴完链接马上调 `mockit_get_review`**(参数 id,传 `wait: 600`)挂起等待,用户不必审完回对话通知你:
   - 用户一裁决,调用立刻返回裁决与批注;等到超时返回的仍是待审状态,属正常结果,再调一次接着等;
   - 若报 `-32001` 超时错误,说明宿主(如 Claude Code 桌面版)对工具调用有 60 秒硬上限——改用 `wait: 50` 循环:每次到时返回待审就再调一次,直到拿到裁决;
   - **累计等满 30 分钟仍待审**:停止等待,告诉用户"还没审,审完告诉我",**并再次附上审核链接**,等用户回话再取。
4. **拿到裁决**:
   - `approve` / `choose`(含选中候选)→ 按选中候选继续实现;
   - `reject` + 批注 → 打回必带批注,批注就是修改依据;按批注修改后**重新 submit**(不支持覆盖更新,历史留痕是特性),在新提交的 `note`(说明)里写明回应了哪些批注,并把**新的**审核链接贴给用户。
5. **`mockit_list`**(status / limit 可选):需要翻旧账时用,查看历史提交简列与当时选了哪版。

## 错误应对

- 报"无法确定手机可达地址" → 请用户在 `~/.mockit/config.json` 配 `"external_url": "域名或IP"`(只填主机名,不带端口),然后重试;
- 报"疑似卡死,请人工处置" → 请用户手工结束进程;下次调用工具时服务自动复活;
- 报"启动中退出,可手工运行 mockit serve 查看报错" → 请用户手工跑一次 `mockit serve`;
- 报 `-32001` 超时错误(宿主对工具调用有约 60 秒硬上限) → `get_review` 改用 `wait: 50` 循环等待,其余工具稍等重试。
- 调用超时 → 稍等重试一次。

## 约束

- 候选 1~6 个;单文件 ≤20MB;zip 必须在根目录含 index.html;
- 服务器不做构建、不做鉴权(只在受信网络可达)——要构建的产物你自己构建完再交;
- 任何拿到审核链接的人都能裁决(如你转给同事),先裁决的生效;
- 已审(reviewed)是终态不可改;要改就重新提交;
- 页面文件 14 天自动清理(已审记录留 90 天)——**别向用户承诺"链接永久有效"**;服务重启若端口漂移,旧链接失效,用 `mockit_get_review` 取新的审核链接,或重新提交;
- 重要裁决结论自己存档到对话或笔记里；
- 用户不主动看就没人审——**提醒用户去拍板(附审核链接),是你工作流的必做一步**。

## 升级与新版提醒（mockit_upgrade）

mockit 还有第四个工具 `mockit_upgrade`，负责升级与版本查询，使用边界：

- **仅在用户明确要求升级 mockit 或查看升级版本时才调用**：`check_only: true` 只查当前/最新版本不安装；默认执行完整升级，可用 `version` 指定目标版本 vX.Y.Z（含降级）。勿自发升级。
- 任何工具结果末尾若出现“mockit 有新版 v…（当前 v…）”的一句话提醒，把它转告用户即可，是否升级由用户决定。
- 升级完成后，按报告提醒用户：**完全退出并重启 Claude Code**（只开新会话不够）；正在运行的 serve 不受影响。
- 结果末尾出现“本会话 MCP 版本（…）旧于 serve（…）”时：本会话仍在跑旧代码，功能照常，提醒用户重启 Claude Code 即可对齐。
